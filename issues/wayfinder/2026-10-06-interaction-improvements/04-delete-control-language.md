# 删除控件怎样说明对象、范围和危险程度

## Question

W2/W4 有多处仅显示“×”的删除按钮，部分没有可访问名称；标签/伙伴的删除热区仅 16×16px，W1画像删除则使用较大的文字按钮和确认。请定义一套跨工作坊规则：什么场景可以直接删除、何时确认或提供撤销；图标按钮怎样命名并向键盘/触屏用户说明目标；鼠标与触屏的可点击尺寸如何定；删除在 hover/focus/按下时怎样反馈且不和“关闭/移除标签”混淆。至少覆盖候选市场、指标、渠道行、语料、标签和画像。

建议用对象名进入可访问名称（如“删除候选市场：华东”），尺寸和确认规则需要给出统一的目标值/例外。

## Resolution

用户选择 A：按风险分层。

- 候选市场、单条渠道行、标签直接删除，并立即提供短暂的「撤销」入口。关键伙伴按单条标签类操作处理；有连带删除或关联影响的入口按确认类处理。
- 指标、单条真实/模拟语料、画像删除前先确认。确认明确显示对象及影响：指标说明受影响的评分/权重引用；语料说明旧 LDA 结果失效及主题关联清除；画像说明场景关联取消、答卷画像指向失去但历史答卷保留。整组删除与清空也先确认。
- 确认操作使用「取消」与「删除{对象类型}」等明确按钮，列出对象名称、数量、连带影响及是否可撤销。取消保留原数据。
- 直接删除反馈为「已删除{对象类型}：{对象名}」，并提供「撤销」。撤销必须恢复原内容、原位置及关联状态，不仅重新增加一个空项；入口存在期间须可用键盘和触屏操作。具体时长在实现规格中统一确定。
- 可访问名称包含动作、对象类型和对象名，如「删除候选市场：华东」「删除二级渠道：直营店」。无名称或重复名称时加入行号；语料使用来源和条目编号。图标按钮的 hover/focus 说明与可访问名称一致。
- 删除点击区域桌面至少 24×24 CSS px，触屏至少 44×44 CSS px；× 的视觉大小可以保持较小，扩大区域不得与相邻控件重叠。
- hover 与 focus 使用一致的危险反馈，键盘焦点保持清晰轮廓；按下提供即时状态反馈。触屏无需 hover 也能辨认并完成操作。具体色彩/按下样式在 06 票统一。
- 「关闭」只关闭界面，「取消关联」只解除关联，均采用对应名称；删除控件明确标明删除目标，不能仅靠 × 或颜色解释性质。

## Acceptance

撤销时长及有效范围已由 [08 票](08-undo-window.md) 定案，采用独立 10 秒、hover/focus 暂停及整体工作区替换后失效的规则。

- 候选市场、渠道行、标签/伙伴直接删除后有可操作的撤销；撤销后内容、位置与关联恢复。
- 指标、真实/模拟语料、画像删除先确认，并显示相应影响；取消不改数据。
- 图标按钮均能通过可访问名称识别具体对象；键盘聚焦可看到相同目标说明。
- 鼠标与触屏目标达到上述尺寸，且不与相邻按钮的点击区域重叠。
- focus、按下和触屏操作均有可辨认反馈；关闭、取消关联与删除的名称不同。
- W5 证据块仍只读；修改或删除上游成果通过上游入口完成。
