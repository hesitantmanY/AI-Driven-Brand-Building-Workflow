# 明确窄屏支持边界并验证工作坊布局

## Confirmed decisions

- 用户选择 C：仅桌面可编辑，最低支持宽度为 1024 CSS px。
- 小于 1024px 的视口显示宽度提示；不承诺手机或更窄平板上的编辑能力。
- 用户选择 B：更窄视口显示提示，保留完整桌面界面并允许横向滚动，不增加窄屏只读锁。

## Resolution

- 内容区域最低宽度 1024 CSS px，避免将 SBU 三问和三列卡片压成极窄列。顶栏、工作坊与步骤导航允许换行；判定横条中的说明和动作自然换行。
- 小于 1024px 显示：`当前窗口宽度小于 1024px，不在支持范围内。建议使用电脑或扩大窗口；下方保留桌面界面，可横向滚动。` 提示按可见视口排版，不随内容横向移出。
- 密集表格局部横向滚动，保留可读列宽；受支持视口不应因表格造成整页横向溢出。
- [布局示意原型](05-desktop-layout.prototype.html) 展示 SBU、导航、宽度提示及 W2 评分表。示意不代表产品已经实现或通过浏览器验收。

## Acceptance

- 390×844、768×1024：提示可读，保留桌面布局，可横向滚动访问控件；不承诺完整窄屏编辑体验。
- 1024×768、1440×900：无宽度提示；SBU 三问、判定横条、顶栏及导航无裁切、控件重叠或文字竖排挤压；表格仅局部滚动。
- 窗口跨越 1024px 时提示即时显隐，不重载、不清空数据、不改变页面位置和未保存状态。
- 提示不阻断访问，不将不受支持误写为禁止编辑。

## Original question

W1/SBU 在 390px 视口实测页面宽 592px，关键表单被压窄。产品是否承诺手机/窄屏可编辑，还是只支持桌面浏览？请结合低成本布局原型确定最低支持宽度、主要断点、顶栏/步骤导航处理方式、三列卡片与表格的响应规则，并列出 390px、平板和桌面各一个验收视口。优先展示 W1/SBU 的窄屏前后对照，并检查一个表格密集步骤。
