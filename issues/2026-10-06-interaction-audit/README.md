## 结论与优先级

### 1. 高：历史记录承诺了不存在的自动备份

- 位置：`docs/global-brand-building.html:2709`、`docs/lib/history.js` 的 load、`server/storage.py:203`。
- 页面：“加载前会把当前内容自动备份为『恢复前备份 …』”。后端实际读取版本后直接覆盖 current.json，不创建备份。
- 用户会在误以为可回退的情况下覆盖当前成果。
- 建议：按已有“一键直载、不备份”决定纠正文案，明确“加载将覆盖当前工作区；需要保留请先保存版本”。不应擅自恢复已被否决的自动备份设计。
- 证据级别：前后端代码核对；未对真实数据执行恢复。

### 2. 中：清空范围与确认文案不一致

- 位置：`docs/workshop3.js:377`。
- 复现：加入真实1条、模拟1条，点击真实卡片“清空”，确认“清空全部语料？”。结果真实0条、模拟仍1条。
- 风险：用户误认为建模输入已经全部删除，仍可能使用模拟语料。
- 建议：“清空真实语料”，确认也指明真实条数；模拟区采用对应文案。保留既定真实+模拟混合建模逻辑。

### 3. 中：历史版本重命名失焦，静默丢弃输入

- 位置：`docs/lib/history.js:60`。
- 复现：点重命名，输入新名，点击搜索框。rename调用0次，名称恢复旧值；无保存按钮或Enter提交说明。
- 风险：用户把失焦理解成与其他表单一致的自动保存。
- 建议：明确提供保存/取消，或显示“Enter保存，Esc取消”；失焦规则须与反馈一致。

### 4. 中：窄屏下主要表单被压成竖排，页面横向溢出

- 位置：`docs/global-brand-building.html` 的 `.sbu-grid`、`.sbu-verdict` 等固定多列布局。
- 复现：W1/sbu，390px视口，document scrollWidth=592px。业务三问和说明文字挤成极窄列，控件跨出视口。
- 建议：窄屏切单列；表格局部滚动；核查顶栏与工作坊导航。若产品仅面向桌面，应明确支持宽度。
- 截图：`brand-mobile-audit.png`。

### 5. 中：标签/伙伴删除点击区域只有16×16px

- 位置：`docs/global-brand-building.html:1171`、`:1193`。
- 浏览器实测伙伴删除按钮16×16px。旁边还有线上/线下归属按钮，容易点偏。
- 建议：视觉×保持小尺寸，扩大可点击区域，至少按24px内部审计基线，触屏采用更宽裕尺寸；避免扩大后与邻近控件重叠。24px是本次检查基线，此处不作标准合规判定。

### 6. 中：W2和W4部分×没有删除对象说明

- 位置：`docs/workshop2.js:543`、`:559`、`:577`、`:631`；`docs/workshop4.js:1147`。
- 空工作区浏览器扫描：W2/framework有16个无aria-label/title的×，W4/place有5个。
- 风险：关闭、移除、删除的语义不清，辅助技术无法说明目标。数量随数据变化。
- 建议：给出“删除候选市场{名称}”“删除指标{名称}”“删除二级渠道{名称}”等名称；键盘focus和hover可显示同样说明。

### 7. 中：同名版本弹窗中“取消”实际仍执行另存

- 位置：`docs/lib/savepanel.js:43`、`docs/lib/history.js:80`。
- 代码分支：confirm返回false后，仍调用Archive.create/rename，overwrite=false并自动加后缀。
- 弹窗正文虽解释了“取消→另存”，但与系统按钮的常见含义冲突；用户无法用取消退出操作。
- 建议：明确的三选项“覆盖 / 另存 / 取消”，取消才结束操作。
- 证据级别：代码确认，未在真实版本库写入测试版本。

### 8. 中：W5证据块仍可改上游，与项目只读术语冲突

- 位置：`CONTEXT.md`“证据块”；`docs/workshop5.js:623-633`、`:271`。
- CONTEXT要求“修改去上游，W5只读”；市场矩阵却标“点选设为主战场”，onSelect调用Work2.setTier1并autosave。徽标提示还含实现术语“直接修改共享state”。
- 风险：用户在读策划书时改变市场战略，且误以为只是在选择图表点。
- 建议：按当前CONTEXT将证据块做只读，添加“去目标市场修改”；若另有已确认可编辑决策，应先同步上下文并明确影响范围。
- 证据级别：代码/规格差异，未执行实际战略修改。

## hover与视觉判断

- 实测顶栏当前模式hover前后均为白字/黑底，选中态没有丢失。
- 通用按钮hover上移2px、出现底线；ghost加深描边，部分AI按钮反色。未确认普遍的文字消失问题，也没有证据支持全面重配色。
- `design.md`描述的按钮规则（paper底、hover反色、active缩放）与实际HTML规则不一致。宜选定现有有效规则后同步文档，避免后续修改再引入两套行为。
- 删除操作多为普通ghost或黑底，与新增/加载共享样式；仅靠hover时变warn不足以提前解释后果。建议使用对象文案、危险操作层级、撤销或范围说明共同表达，而非只改红色。
